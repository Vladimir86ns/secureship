# SecureShip

SecureShip is a shipment support chat. Anyone can ask general questions; to see shipment data the visitor verifies
their identity inside the conversation (first name, last name, address, phone number, then a 6-digit code from a mock
SMS typed into a popup). Only then can the assistant look up shipments, and only that customer's own. The chat runs on
a local model through Ollama. A separate admin panel, behind an Auth0 login, manages customers, shipments and packages.

Stack: React 19 + TypeScript + Vite (`frontend/`), FastAPI + SQLAlchemy (async) + Alembic (`backend/`), PostgreSQL 16,
Ollama with `qwen3:8b` (`OLLAMA_MODEL`), Auth0 for admin login only.

## How to run

```bash
cp .env.example .env                                     # fill in the AUTH0_* and VITE_AUTH0_* values
docker compose up --build                                # frontend, backend, postgres
docker compose exec backend python -m scripts.seed_data  # synthetic mock data (upsert, safe to run twice)
```

- Ollama is **not** in Docker: run it on the host with `qwen3:8b` pulled. The backend reaches it at
  `host.docker.internal:11434` (`OLLAMA_BASE_URL`).
- The backend runs `alembic upgrade head` on start.
- Chat: http://localhost:5173/ · Admin: http://localhost:5173/admin · API: http://localhost:8000
  (`/health`, `/openapi.json`).
- The mock SMS code is in the backend log: `docker compose logs -f backend | grep "MOCK SMS"`.

## How to test

```bash
docker compose exec backend python -m pytest -q
cd frontend && npm run build && npm run lint
```

Tests never call the real Ollama or the real Auth0 tenant: the model is replaced with an `AsyncMock` on
`services.chat.chat_completion` (`backend/tests/helpers.py`), and Auth0 is a local fake tenant
(`backend/tests/admin_tokens.py`, `backend/tests/conftest.py`) — any other identity-provider fetch fails the test.
Keep it that way for new tests.

## Rules

- **The identity gate is enforced on the server.** Every tool call goes through `execute_tool` →
  `authorize_tool_call`, and shipment tools through `require_verified` (`backend/services/tools.py`). Never weaken
  it and never rely on the prompt for access control. Only `POST /api/verify` (`check_verification_code`) can make a
  session verified; it is never a model tool.
- **`lookup_shipments` always queries by `session.customer_id`,** never by an id from the model or the user. It accepts
  only an optional `tracking_number`; any other argument is refused.
- **Local model only** for the chat runtime (Ollama). No external LLM APIs in the app.
- **No personal data in logs.** Log names, states, argument names/types and counts, never values. The `[MOCK SMS]`
  line (`backend/services/mock_sms.py`) is the only deliberate exception.
- **Admin login only through Auth0;** admin and chat identities stay separate. `/admin/*` is protected by
  `require_admin` on the whole router; chat routes read only the session cookie, never `Authorization`; the admin client
  (`frontend/src/api/adminMutator.ts`) never sends the chat cookie.
- **Frontend API types and hooks are generated by Orval** from `/openapi.json` into `frontend/src/api/generated/`
  (`frontend/orval.config.ts`). No hand-written API types or fetch calls; do not edit the generated files.
  Regenerate after backend schema changes: `npm run generate:api` in `frontend/` with the backend running.
- **Chat sessions are stored in Postgres** (`chat_sessions`, JSONB transcript, keyed by an httpOnly cookie). No second
  database or session store.
- **All data is synthetic mock data** (`backend/scripts/seed_data.py`, `docs/demo-customers.md`).
- **AI-generated code, diagrams and README are reviewed;** docs must match the code. When code changes, update the
  affected file and line references in `README.md`, `docs/diagrams/` and `docs/security/`.
