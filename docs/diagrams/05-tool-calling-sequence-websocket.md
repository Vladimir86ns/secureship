# 6.3b Tool-calling sequence over WebSockets — Not implemented

Regenerated against the implementation (Week 5). This was an optional upgrade.

**Status: not implemented. Deliberate decision: the chat uses plain HTTP (diagram [04](04-tool-calling-sequence-http.md)).**

There is no diagram here on purpose: no diagram in this folder shows a WebSocket as part of the system.

Why HTTP:

- One request, one answer: `POST /api/chat` returns the assistant's messages and the new state together. There is no
  WebSocket route (`backend/main.py:24-27` registers only HTTP routers) and no WebSocket library in
  `frontend/package.json`.
- All API types and React Query hooks are generated by Orval from `/openapi.json`, which covers HTTP routes only.
- The main reason for a socket in the spec — showing an admin change live — is handled by asking again: every shipment
  question runs a fresh `lookup_shipments`, so the change is visible on the visitor's next question. This was checked by
  hand in Week 4 (`docs/security/admin-separation.md`, manual check table).
